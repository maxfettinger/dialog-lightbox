Docs

Everything the library reads and writes, on one page.

The library finds the parts of your page by their data-dlb-* attributes, adds the behaviour, and reports its state as attributes your CSS can use. It ships no look of its own: dialog-lightbox.css only does layout, in the cascade layer dialog-lightbox, so your styles win without fighting specificity.

Links

Every <a href> inside the gallery is a slide, in order. Its first <img> is the thumbnail, which has to show the whole photo; crop it with object-fit: cover if you want frames, and the box opens by zooming out of the frame.

Attribute
hrefThe large image or the video file
data-dlb-type="video"A video; the thumbnail is its poster and should be its first frame
data-dlb-srcsetsrcset for the large image; its largest w is taken as the native width
data-dlb-width, data-dlb-heightNative size, if you have it, so the box can open and zoom at once. Without them the thumbnail's aspect ratio is used
data-dlb-idA stable id for #dlb= links. Without it the id is <gallery id>-<number>
data-dlb-noaudioThe video has no sound; the mute button is disabled

The dialog

One <dialog> serves every gallery on a page. Only the viewport is required; every other part is optional.

Element
[data-dlb-viewport]The slides go here and gestures start here. Its padding is the room the photo leaves free for your buttons and caption
[data-dlb-close], [data-dlb-prev], [data-dlb-next], [data-dlb-zoom]Buttons; disabled where they can't act
[data-dlb-counter]Gets "3 / 16"
[data-dlb-play], [data-dlb-mute]Video buttons; aria-pressed is true while playing or muted, so label them "Play" and "Mute"
[data-dlb-fullscreen]Opens the video in the browser's own fullscreen player (Apple's player on iPhone). Disabled on photos
[data-dlb-progress]Gets --dlb-progress from 0 to 1 while a video plays
<template data-dlb-overlay>Copied over each slide's photo or video as <div data-dlb-overlay>, so the controls inside move, swipe and shrink with the media. ="video" or ="image" limits it to one type

JavaScript

import { lightbox } from "dialog-lightbox";

const box = lightbox({ gallery, dialog, loop: false, history: true });
box.on("change", (slide) => { /* update a caption */ });
OptionDefault
galleryElement whose links are the slides
dialogYour <dialog>
loopfalseAfter the last slide comes the first
historytrueThe back button closes the box; #dlb=<id> opens a slide
Returns
open(index = 0), close()Open on a slide, or close
next(), prev(), goTo(index)Move while open
current, countThe current slide (null while closed) and the number of slides
videoThe one <video> element
on(event, handler)"open", "change" or "close"; returns a function that removes the handler. change also fires right after open
destroy()Closes without animation and removes every listener

A slide is { index, id, type, link }, where link is the thumbnail's <a>.

State for your CSS

On the dialog: data-dlb-type (image or video), data-dlb-first, data-dlb-last, data-dlb-loading, data-dlb-error, data-dlb-zoomable, data-dlb-zoomed, data-dlb-ui-hidden (after a tap on a photo), data-dlb-paused, data-dlb-muted, data-dlb-noaudio, data-dlb-animating (opening and closing zoom, drag down) and data-dlb-moving (anything moving).

Custom properties: --dlb-opacity goes from 0 to 1 while the box opens and back while it closes, for the backdrop. --dlb-media-x, -y, -width and -height give the rectangle where the current photo or video rests.

The current slide has data-dlb-current; the others are inert.

Good to know

  • A CSS reset doesn't need undoing: the slide's media get max-width: none inline.
  • The current slide holds two images, the thumbnail and the large one on top: [data-dlb-current] img:last-of-type is the large one.
  • Browsers: Safari 17.4, Chrome and Edge 122, Firefox 132 and later (Baseline 2024).
